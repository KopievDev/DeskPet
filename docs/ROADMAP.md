# DeskPet — roadmap

Настольный AI-компаньон для **ESP32-S3**. **Аппаратная стратегия: сейчас LILYGO T-Display-S3 с IPS LCD (ST7789V, 170×320), после успешного прототипа — отдельная версия на AMOLED (RM67162, 240×536).** Принципы: offline-first, приватность по умолчанию, модульная прошивка, работа с iPhone, Android и Mac.

> Номера версий ниже — план разработки, не выпущенные релизы. Очерёдность после 0.1 можно корректировать после проверки платы.

## 0.1 · Animated Face (PR #1)
- [x] Аппаратный профиль обычной T-Display-S3, LCD 320×170, ландшафтная ориентация.
- [x] Глаза, зрачки, моргание, самостоятельные движения взгляда.
- [x] **17 эмоций**: neutral / happy / curious / surprised / sleepy / angry / sad / love / confused / excited / playful / smug / furious / embarrassed / dizzy / bored / bewildered.
- [x] У Surprised увеличенные зрачки с ограниченным движением внутри глаз.
- [x] Новые характерные детали: сердечки для Love, слеза для Sad, подмигивание Playful, асимметрия Confused, строгие веки Angry, искры и подпрыгивание Excited.
- [x] Ещё пять характеров: самодовольный `Smug`, трясущийся от злости `Furious`, застенчивый `Embarrassed`, вращающиеся X-зрачки `Dizzy`, скучающий `Bored`.
- [x] **Bewildered / недоумение** — правый зрачок медленно уходит к наружному краю глаза и возвращается за 4,8 с с паузами и плавным ускорением; разные положения бровей; анимированный ротик с каплей слюны в безопасной области 320×170.
- [x] Serial-команда `bewildered` и выбор через USER / `demo on`, русская реплика `ЭТО КАК?!` при явном включении `sass on`.
- [ ] Проверить Bewildered на настоящей IPS: зрачок не выходит из белка глаза, капля не пересекает нижние подписи, цикл не дёргается на границе и корректно совмещается с морганием.
- [x] **Опциональные комикс-реплики на русском**: небольшой отдельный 8×12 пиксельный шрифт с нужными кириллическими глифами, плашка с мягким появлением/исчезновением, ограниченное время отображения.
- [x] **Цензурированные выражения** (`ИДИ НА Х#$#!!`, `НУ ВСЕ, БЛ#!!` и т. п.) только после явного `sass on`; `sass off` сразу скрывает, настройки **не сохраняются** после перезагрузки, нет передачи текста по сети.
- [x] `quip` для повторного вывода текущей фразы; `demo on` теперь показывает 17 эмоций. USER/BOOT по-прежнему работают без сети.
- [ ] Проверить кириллицу, размер плашки, длительность и контраст реплик на реальном дисплее при `sass on` / `sass off`, плюс производительность отрисовки и память.
- [x] Выразительные брови: отдельные мягко анимированные высота, изгиб и наклон; асимметрия для Curious.
- [x] Форма глаз зависит от эмоции: Happy — улыбающиеся дуги вместо прямоугольной выемки; Curious — разные веки и высота глаз; Surprised — округлые глаза; Sleepy — полуприкрытые веки.
- [x] **Плавная трансформация глаз между эмоциями**: интерполяция размеров, открытости, зрачков, наклонов верхних век и бровей без выделения памяти на каждом кадре.
- [x] **Happy / Love / Playful**: переход между разными силуэтами через мягкое закрытие и открытие глаз (~360 мс), без визуального скачка в момент замены формы.
- [x] Повторные команды посреди перехода не раскрывают глаза резко; обычное моргание и Sleep остаются работоспособными.
- [x] **Serial-демо `demo on` / `demo off`**: циклический показ 17 эмоций каждые 1,8 секунды без блокировки UI, ручные действия отменяют демо.
- [x] **Локальный ReactionController без сетевого транспорта**: результат сборки через Serial `event build-success` → Excited / `event build-failure` → Furious (4,5 с), затем возвращается последняя ручная эмоция.
- [x] **Idle → Bored** через 120 секунд отсутствия активности (настраиваемый интервал 15–3600 секунд); `idle on/off`, `status`, ручной приоритет, отмена временных событий, пауза автоматических эмоций во сне и в деморежиме.
- [x] **macOS CLI bridge для `xcodebuild`**: opt-in через `DESKPET_PORT`, отправка Serial-события по реальному exit code; ошибки порта не меняют результат сборки.
- [x] Независимые от ESP32 host-тесты контроллера реакций на переходы, повторные события и переполнение `millis()`; отдельная регрессия списка эмоций, Serial-команд и кириллического шрифта.
- [ ] Протестировать реальные USB-уведомления от `xcodebuild`, тайм-аут Bored, реакцию на сон и разные частоты сборок на IPS.
- [ ] Позже: интеграция с **событиями Xcode GUI и GitHub/Xcode сборок** через macOS-приложение, безопасный канал связи вместо USB Serial, настройки реакций в UI.
- [ ] Проверить переходы **Neutral → Surprised**, **Neutral → Angry**, **Happy → Love → Playful**, **Sleepy → Neutral** и быстрое последовательное нажатие USER на реальном IPS.
- [ ] Оценить **все 17 эмоций, брови и увеличенные зрачки Surprised на реальной IPS-плате**: моргание, расположение на 320×170, FPS, читаемость и контраст цветов.
- [x] Сон, реакция на две встроенные кнопки, Serial-команды.
- [x] Off-screen sprite в PSRAM для снижения мерцания.
- [ ] Подтвердить компиляцию PlatformIO на Mac.
- [ ] Проверить экран, обе кнопки, FPS и память на физической плате.
- [ ] Разделить `FaceAnimator` и LCD-зависимое рисование через `DisplayDriver` / `BoardProfile` без изменения пользовательского поведения; **первым целевым профилем остаётся IPS LCD**, AMOLED пока не реализуем.

## 1.0 · Personality Studio (характер питомца)
- [ ] **Редактор характера** в macOS-приложении (позже — на телефоне): дружелюбие, сарказм, юмор, дерзость, эмоциональность, болтливость, инициативность.
- [ ] Настройка **ненормативной лексики**: Выкл. (по умолчанию) / Лёгкая / Умеренная / Без цензуры — только по явному выбору пользователя.
- [ ] Отдельные переключатели **«Мат в чате»** и **«Мат вслух»**; быстрый безопасный режим, например для офиса или присутствия детей.
- [ ] Пресеты: Милашка, Ассистент, Хулиган, Бес, Гений, Геймер, Custom; возможность создать, сохранить, экспортировать и импортировать профиль.
- [ ] Пользовательское описание характера (prompt) с предпросмотром тестовых реплик и объяснением, что провайдеры ИИ могут ограничивать стиль речи.
- [ ] Контекстные реакции: ошибка сборки, успешный PR, напоминание о перерыве, поглаживание, входящий вызов — характер влияет на фразы, эмоции и движения, а не только на текст.
- [ ] Единая типизированная схема **PersonalityProfile** (версия, настройки речи, мимики, голосового режима, инициативности) с валидацией и миграциями.
- [ ] Характер применяется и к облачным, и к локальным моделям; гарантировать стиль/бранную лексику невозможно — это зависит от модели и голосового движка.
- [ ] Пользовательские инструкции изменяют тон, **но не разрешения**: все внешние действия идут через allowlist, подтверждения и контроль приватности.

- [ ] Независимая настройка **«Мат вслух»** и беззвучного режима, синхронизация с Personality Studio; осмысленный безопасный вариант по умолчанию.

- [ ] Исследовать **MLX-Audio** и альтернативные способы локального инференса на Apple Silicon: поддержка русского языка, качество/интонации, RAM, размер, задержка первого фрагмента, лицензии и совместимость моделей.
- [ ] Опциональный облачный TTS (например, OpenAI) **только с разрешения**; локальный режим не требует отправки текста в облако.
- [ ] Менеджер голосовых моделей **в один клик**: выбор, загрузка, прогресс, тестирование, остановка, удаление, объём диска/RAM и авто-выгрузка при простое.
- [ ] Голосовой профиль **VoiceProfile**: выбранный движок/модель/голос, настройки, пресет эмоций, версионирование и перенос между Mac и аппаратным DeskPet без смены голоса при переключении LLM.
- [ ] **Voice Design**: описать желаемый голос словами, сгенерировать тестовое звучание, сохранить пресет — при наличии подходящего движка и достаточных ресурсов.
- [ ] Эмоциональный пайплайн: LLM возвращает валидируемые **text + emotion + voiceStyle**, TTS подбирает интонацию, DeskPet синхронизирует глаза/движения с состояниями речи без блокировки кнопок и уведомлений.
- [ ] Аудиопоток Mac → ESP32-S3 по Wi-Fi: буферизация, контроль задержки, прерывание ответа, корректное восстановление после обрыва; тест с **INMP441 + MAX98357A** и дисплеем.
- [ ] Оптимизировать память: голос не обязан постоянно держать тяжёлый TTS в RAM; лёгкий fallback остаётся доступен при выгрузке нейросетевого движка.
- [ ] **TTS memory profiles**: `Eco` — системный macOS TTS или Piper; `Balanced` — Qwen3-TTS 0.6B 8-bit; `Quality` — более тяжёлая модель (Qwen3-TTS 1.7B только после бенчмарка). Не загружать нейросетевой TTS в `Eco`.
- [ ] Сравнить **4-bit / 8-bit / BF16** варианты Qwen3-TTS 0.6B: измерить реальный размер скачивания/на диске и **пик unified memory** во время генерации, включая аудиокодек, KV-cache и буферы. Не считать размер весов равным потреблению RAM.
- [ ] В UI показывать **примерную потребность в RAM до установки** и фактическое потребление при воспроизведении; предупредить о нехватке памяти на Mac с 8 ГБ.
- [ ] Реализовать **lazy loading** и выгрузку TTS после бездействия (по умолчанию исследовать 2 минуты); пресеты `Сразу / 2 минуты / Всегда загружена`, отображать статус `Загружена / Выгружена`.
- [ ] **Планировщик памяти LLM + TTS + STT**: учитывать одновременное потребление Qwen3 1.7B и Qwen3-TTS 0.6B, приоритет работы интерфейса и системных приложений, последовательную загрузку/выгрузку при недостатке RAM.
- [ ] Профили производительности для **8 / 16 / 32 ГБ** unified memory, замеры на Apple Silicon: peak RAM, memory pressure, swap, холодный/тёплый старт, время до первого звука и real-time factor на русском тексте.
- [ ] **Нефиксированные ориентиры для планирования, до бенчмарка**: Qwen3-TTS 0.6B 4-bit ~2–5 ГБ RAM, 8-bit ~3–6 ГБ, BF16 ~4–8 ГБ; одновременно с Qwen3 1.7B возможно ~5–10+ ГБ суммарно (без macOS и STT). Уточнить числа на реальных сборках; не обещать измеренной экономии и скорости без испытаний.
- [ ] При memory pressure — автоматически снижать профиль голоса до Piper/macOS TTS (с предупреждением) вместо падения приложения; в режиме `Eco` поддержать стабильную озвучку даже при выгруженных LLM/TTS.
- [ ] Проверить лицензию и коммерческое использование **каждой** выбранной модели голоса, движка и голосового набора отдельно.

## Hardware roadmap · IPS first → AMOLED later

**Принятое решение:** не менять железо в текущем цикле — сначала довести до стабильного прототипа имеющуюся **LILYGO T-Display-S3 IPS LCD**, затем отдельно портировать прошивку на **T-Display-S3 AMOLED 1.91″**. Покупать AMOLED и перетрассировать PCB заранее не требуется.

### Phase A · IPS LCD (текущий прототип)
- [ ] Завершить bring-up дисплея ST7789V (170×320; в ландшафте 320×170), кнопок, эмоций и FPS.
- [ ] Отладить взаимодействие со звуком, BLE, Wi-Fi и датчиками на текущей аппаратной ревизии.
- [ ] Развивать схему и `.pcblab` плату расширения **только под IPS-версию**; не считать нынешний проект проверенным для изготовления.
- [ ] Зафиксировать используемые GPIO, I²S/I²C, линии питания и разъёмы в документации конкретной ревизии.

### Phase B · Display abstraction (заложить сейчас, без замены платы)
- [ ] Интерфейс `DisplayDriver`: инициализация, кадр, яркость, включение/сон; отдельный `BoardProfile` с таблицей GPIO и возможностями (touch, кнопки, подсветка).
- [ ] Перевести UI-анимации и координаты персонажа на относительные значения, учитывать aspect ratio, safe area и разные ориентации.
- [ ] Проверить расходы PSRAM на буферы и частоту кадров отдельно для 320×170 и 536×240.
- [ ] Не смешивать логику эмоций/уведомлений с конкретной библиотекой LCD или QSPI.

### Phase C · AMOLED 1.91″ (после готового IPS-прототипа)
- [ ] Добавить аппаратный профиль **LILYGO T-Display-S3 AMOLED / RM67162**, разрешение **240×536** (ландшафт 536×240), интерфейс QSPI.
- [ ] Подключить драйвер AMOLED и отдельно проверить инициализацию, ориентацию, яркость, FPS, потребление PSRAM и режим сна.
- [ ] **Переразвести GPIO** аудио, I²C, датчиков и сервоприводов для AMOLED-платы: схема IPS несовместима без ревизии (например, LCD GPIO17/18 уже заняты AMOLED).
- [ ] Ввести профилактику выгорания AMOLED: авто-сон/затемнение, отсутствие постоянных ярких неподвижных элементов.
- [ ] Сравнить видимость глаз, энергопотребление и температуру, проверить touch только если он есть в купленной ревизии.
- [ ] Для **собственной PCB** выбрать точную AMOLED-панель с документацией и подтверждённым интерфейсом/FPC; не считать готовую T-Display-S3 и «голую» AMOLED-панель электрически взаимозаменяемыми.
- [ ] Проверить, что те же эмоции, уведомления, характер, голос и конфигурация работают на IPS и AMOLED без форка бизнес-логики.

## Acceptance criteria для поддержки двух дисплеев

1. После завершения Phase B текущая **IPS-плата** продолжает работать как раньше; изменений GPIO и требований к железу на данном этапе нет.
2. Рендеринг использует независимые от конкретного дисплея координаты и не обрезает глаза на обоих соотношениях сторон.
3. Для каждой аппаратной ревизии есть отдельные таблицы занятых GPIO и проверенные драйверы; подключение аудио и датчиков не конфликтует с дисплеем.
4. AMOLED-портирование начинается отдельным этапом **после подтверждённой работы IPS-прототипа**, без принудительной замены существующего оборудования.

## Later · Ecosystem
- [ ] iOS-приложение для дополнительных настроек/кастомизации (ANCS-приём не должен требовать его постоянной работы).
- [ ] Локальная память питомца с управлением сроками хранения и редактор сценариев поведения (см. Personality Studio и Virtual DeskPet выше).
- [ ] Смена платы/экрана без переписывания движка персонажа (по этапам IPS → AMOLED выше).
- [ ] Дополнительные каналы интеграции и необязательный удалённый доступ через защищённый шлюз.

## Acceptance criteria для Voice Studio

1. На Mac можно услышать выбранную русскоязычную тестовую фразу **до подключения ESP32**, без терминала и ручного развёртывания TTS.
2. Можно выбрать доступный голос, изменить скорость и сохранить выбор; неподдерживаемые возможности конкретного движка корректно отключены.
3. При наличии эмоционального TTS одна фраза воспроизводится с как минимум двумя различимыми интонациями; на базовом движке работает понятный fallback.
4. Голос сохраняется при переключении LLM (локальная/облачная), а тот же VoiceProfile используется DeskPet Virtual и физическим роботом.
5. Пользователь явно выбирает, передавать ли текст для облачной озвучки; локальные голоса работают без интернета после установки.
6. Переключение «Мат вслух» не влияет на текстовую настройку и не обходит ограничения выбранного TTS.
7. Отключение/удаление большой TTS-модели освобождает память, не ломает анимации и не мешает базовым функциям питомца.
8. Пользователь видит расход памяти и может переключать `Eco / Balanced / Quality` без перезапуска приложения; конфигурация не превышает доступную память без предупреждения.
9. Для `Qwen3-TTS 0.6B` задокументированы реальные измерения 4-bit, 8-bit и BF16: пик unified memory, swap, размер модели и задержка первого звука на короткой русской фразе.
10. После установленного интервала простоя тяжёлый TTS выгружается, а звуковые уведомления и системный fallback продолжают работать.

## Acceptance criteria для Personality Studio и Virtual DeskPet

1. Новому пользователю по умолчанию назначен нейтральный характер без мата; ненормативная лексика включается отдельно для текста и голоса.
2. Характер меняет тон и анимации в тестовых сценариях, не отключая проверки команд и разрешений.
3. Пользователь может переключать пресеты и редактировать Custom-профиль, не теряя настройки после перезапуска.
4. DeskPet Virtual работает без ESP32, показывает эмоции и поддерживает локальный чат после установки модели.
5. При подключении физического DeskPet профиль и настройки синхронизируются без дублирования уведомлений; отключение устройства не ломает виртуального питомца.
6. Локальную модель можно скачать и удалить через интерфейс; при простое приложение умеет выгружать модель из памяти.

## Acceptance criteria для BLE-уведомлений

1. iPhone: после разрешённого сопряжения DeskPet получает поддерживаемые системой уведомления через ANCS **без интернета и без работающего на Mac Gateway**.
2. Android: с установленным приложением и выданным разрешением уведомления доставляются на DeskPet локально по BLE.
3. Уведомления не обрывают анимации и не блокируют управление; карточка автоматически исчезает.
4. После разрыва и восстановления соединения не происходит бесконечных повторов старых событий.
5. Чувствительное содержимое никогда не отправляется в AI без отдельного opt-in.
