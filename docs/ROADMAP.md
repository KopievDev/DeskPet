# DeskPet — roadmap

Настольный AI-компаньон для **ESP32-S3**. **Аппаратная стратегия: сейчас LILYGO T-Display-S3 с IPS LCD (ST7789V, 170×320), после успешного прототипа — отдельная версия на AMOLED (RM67162, 240×536).** Принципы: offline-first, приватность по умолчанию, модульная прошивка, работа с iPhone, Android и Mac.

> Номера версий ниже — план разработки, не выпущенные релизы. Очерёдность после 0.1 можно корректировать после проверки платы.

## Pet Needs — энергия, настроение и внимание (PR #1)

- [x] **PetNeeds.h** — автономный C++11-контроллер трёх показателей **Energy / Mood / Attention** (0–100, старт E78/M70/T65). Без NVS, сети, фоновых задач, датчиков и аллокаций.
- [x] В бодрствовании E/T снижаются по 1 за 4 минуты, M снижается по 1 за 9 минут; во сне E восстанавливается по 1 в минуту, M/T не падают. Смена sleep↔wake сбрасывает дробные накопления, исключая мгновенные скачки.
- [x] Поглаживание USER: +12 настроение, +20 внимание; обычное нажатие +3 внимание; двойное +4/+8; успешная/неуспешная сборка изменяет M на +5/−6, ошибка также −1 энергия. `needs coffee` и `needs play` — ручная виртуальная забота.
- [x] При низких потребностях и свободной Neutral: раз в ~90 секунд Nerd с чашкой кофе, Derp/Gremlin с восклицательным знаком, Bewildered со звездой. Никакого принудительного сна; запущенный скетч имеет таймер 4,8 с и уступает ручной эмоции / Xcode / Mac Activity / Demo.
- [x] `needs status/reset/on/off/set E M T/show coffee|attention|cheer`, три значения компактно показываются в нижнем HUD рядом с `A:50`; рисунок чашки, восклицательного знака и звезды без выделения новых графических буферов.
- [x] `pet_needs_test.cpp` проверяет явную заботу, интервалы, строгое ограничение 0–100, сон, переходы, отключение, очередь скетчей и переполнение `millis()`; исходники проверяются в `check_face_assets.py`.
- [ ] Проверить на настоящей T-Display-S3 читаемость E/M/T, полноту HUD, расположение иконки кофе, скорость анимаций, потребление памяти и отсутствие конфликтов с ручными эмоциями.
- [ ] По мере развития — опциональная настройка скорости изменения потребностей из macOS menu bar-приложения, выключенная по умолчанию запись в NVS (только по желанию пользователя).

## Hardware roadmap · IPS first → AMOLED later

**Принятое решение:** не менять железо в текущем цикле — сначала довести до стабильного прототипа имеющуюся **LILYGO T-Display-S3 IPS LCD**, затем отдельно портировать прошивку на **T-Display-S3 AMOLED 1.91″**. Покупать AMOLED и перетрассировать PCB заранее не требуется.

### Phase A · IPS LCD (текущий прототип)
- [ ] Завершить bring-up дисплея ST7789V (170×320; в ландшафте 320×170), кнопок, эмоций и FPS.
- [ ] Отладить взаимодействие со звуком, BLE, Wi-Fi и датчиками на текущей аппаратной ревизии.
- [ ] Развивать схему и `.pcblab` плату расширения **только под IPS-версию**; не считать нынешний проект проверенным для изготовления.
- [ ] Зафиксировать используемые GPIO, I²S/I²C, линии питания и разъёмы в документации конкретной ревизии.

### Phase B · Display abstraction (заложить сейчас, без замены платы)
- [ ] Интерфейс `DisplayDriver`: инициализация, кадр, яркость, включение/сон; отдельный `BoardProfile` с таблицей GPIO и возможностями (touch, кнопки, подсветка).
- [ ] Перевести UI-анимации и координаты персонажа на относительные значения, учитывать aspect ratio, safe area и разные ориентации.
- [ ] Проверить расходы PSRAM на буферы и частоту кадров отдельно для 320×170 и 536×240.
- [ ] Не смешивать логику эмоций/уведомлений с конкретной библиотекой LCD или QSPI.

### Phase C · AMOLED 1.91″ (после готового IPS-прототипа)
- [ ] Добавить аппаратный профиль **LILYGO T-Display-S3 AMOLED / RM67162**, разрешение **240×536** (ландшафт 536×240), интерфейс QSPI.
- [ ] Подключить драйвер AMOLED и отдельно проверить инициализацию, ориентацию, яркость, FPS, потребление PSRAM и режим сна.
- [ ] **Переразвести GPIO** аудио, I²C, датчиков и сервоприводов для AMOLED-платы: схема IPS несовместима без ревизии (например, LCD GPIO17/18 уже заняты AMOLED).
- [ ] Ввести профилактику выгорания AMOLED: авто-сон/затемнение, отсутствие постоянных ярких неподвижных элементов.
- [ ] Сравнить видимость глаз, энергопотребление и температуру, проверить touch только если он есть в купленной ревизии.
- [ ] Для **собственной PCB** выбрать точную AMOLED-панель с документацией и подтверждённым интерфейсом/FPC; не считать готовую T-Display-S3 и «голую» AMOLED-панель электрически взаимозаменяемыми.
- [ ] Проверить, что те же эмоции, уведомления, характер, голос и конфигурация работают на IPS и AMOLED без форка бизнес-логики.

## Acceptance criteria для поддержки двух дисплеев

1. После завершения Phase B текущая **IPS-плата** продолжает работать как раньше; изменений GPIO и требований к железу на данном этапе нет.
2. Рендеринг использует независимые от конкретного дисплея координаты и не обрезает глаза на обоих соотношениях сторон.
3. Для каждой аппаратной ревизии есть отдельные таблицы занятых GPIO и проверенные драйверы; подключение аудио и датчиков не конфликтует с дисплеем.
4. AMOLED-портирование начинается отдельным этапом **после подтверждённой работы IPS-прототипа**, без принудительной замены существующего оборудования.

## Later · Ecosystem
- [ ] iOS-приложение для дополнительных настроек/кастомизации (ANCS-приём не должен требовать его постоянной работы).
- [ ] Локальная память питомца с управлением сроками хранения и редактор сценариев поведения (см. Personality Studio и Virtual DeskPet выше).
- [ ] Смена платы/экрана без переписывания движка персонажа (по этапам IPS → AMOLED выше).
- [ ] Дополнительные каналы интеграции и необязательный удалённый доступ через защищённый шлюз.

## Acceptance criteria для Voice Studio

1. На Mac можно услышать выбранную русскоязычную тестовую фразу **до подключения ESP32**, без терминала и ручного развёртывания TTS.
2. Можно выбрать доступный голос, изменить скорость и сохранить выбор; неподдерживаемые возможности конкретного движка корректно отключены.
3. При наличии эмоционального TTS одна фраза воспроизводится с как минимум двумя различимыми интонациями; на базовом движке работает понятный fallback.
4. Голос сохраняется при переключении LLM (локальная/облачная), а тот же VoiceProfile используется DeskPet Virtual и физическим роботом.
5. Пользователь явно выбирает, передавать ли текст для облачной озвучки; локальные голоса работают без интернета после установки.
6. Переключение «Мат вслух» не влияет на текстовую настройку и не обходит ограничения выбранного TTS.
7. Отключение/удаление большой TTS-модели освобождает память, не ломает анимации и не мешает базовым функциям питомца.
8. Пользователь видит расход памяти и может переключать `Eco / Balanced / Quality` без перезапуска приложения; конфигурация не превышает доступную память без предупреждения.
9. Для `Qwen3-TTS 0.6B` задокументированы реальные измерения 4-bit, 8-bit и BF16: пик unified memory, swap, размер модели и задержка первого звука на короткой русской фразе.
10. После установленного интервала простоя тяжёлый TTS выгружается, а звуковые уведомления и системный fallback продолжают работать.

## Acceptance criteria для Personality Studio и Virtual DeskPet

1. Новому пользователю по умолчанию назначен нейтральный характер без мата; ненормативная лексика включается отдельно для текста и голоса.
2. Характер меняет тон и анимации в тестовых сценариях, не отключая проверки команд и разрешений.
3. Пользователь может переключать пресеты и редактировать Custom-профиль, не теряя настройки после перезапуска.
4. DeskPet Virtual работает без ESP32, показывает эмоции и поддерживает локальный чат после установки модели.
5. При подключении физического DeskPet профиль и настройки синхронизируются без дублирования уведомлений; отключение устройства не ломает виртуального питомца.
6. Локальную модель можно скачать и удалить через интерфейс; при простое приложение умеет выгружать модель из памяти.

## Acceptance criteria для BLE-уведомлений

1. iPhone: после разрешённого сопряжения DeskPet получает поддерживаемые системой уведомления через ANCS **без интернета и без работающего на Mac Gateway**.
2. Android: с установленным приложением и выданным разрешением уведомления доставляются на DeskPet локально по BLE.
3. Уведомления не обрывают анимации и не блокируют управление; карточка автоматически исчезает.
4. После разрыва и восстановления соединения не происходит бесконечных повторов старых событий.
5. Чувствительное содержимое никогда не отправляется в AI без отдельного opt-in.
